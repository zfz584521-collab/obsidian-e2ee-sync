# 多用户仓库隔离说明

这个文档专门说明一个问题：

```text
张三有两台电脑要同步。
李四也有两台电脑要同步。
如果他们使用同一个对象存储服务，会不会数据串到一起？
```

结论先说：

```text
服务地址、访问密钥 ID、访问密钥密码，可以相同。
但不同用户的仓库 ID / 同步通道必须不同，同步密码也应该不同。
```

---

## 一、同步配置可以理解成三层

可以把对象存储理解成一个大仓库：

```text
对象存储桶 = 一个大仓库
仓库 ID / 同步通道 = 大仓库里的一个房间
同步密码 = 房间里文件的加密钥匙
```

所以真正决定“数据是不是同一份”的，主要是：

```text
仓库 ID
同步通道前缀
```

真正决定“别人能不能看懂内容”的，是：

```text
同步密码
```

真正决定“谁有权限访问对象存储”的，是：

```text
访问密钥 ID
访问密钥密码
```

---

## 二、哪些配置可以相同

如果张三和李四使用同一个对象存储账号，下面这些可以相同：

```text
服务地址
存储桶名称
访问密钥 ID
访问密钥密码
区域
```

这样做的含义是：

```text
张三和李四都能访问同一个对象存储桶。
```

这在技术上可以用，但安全性不是最高。

---

## 三、哪些配置必须不同

不同用户之间，下面这些必须不同或强烈建议不同：

```text
仓库 ID
同步通道前缀
同步密码
```

最关键的是：

```text
仓库 ID / 同步通道前缀不能一样。
```

如果仓库 ID / 同步通道前缀一样，插件会认为他们在同步同一份远端数据。

同步密码也应该不同。即使远端路径不小心相同，不同同步密码也能避免内容被正常解密。

---

## 四、张三和李四推荐怎么配置

### 方案一：最推荐，不同用户使用不同存储桶

张三：

```text
服务地址：同一个对象存储服务地址
存储桶名称：zhangsan-obsidian-sync
访问密钥 ID：张三自己的密钥
访问密钥密码：张三自己的密钥密码
仓库 ID：zhangsan-vault
同步密码：张三自己的同步密码
```

李四：

```text
服务地址：同一个对象存储服务地址
存储桶名称：lisi-obsidian-sync
访问密钥 ID：李四自己的密钥
访问密钥密码：李四自己的密钥密码
仓库 ID：lisi-vault
同步密码：李四自己的同步密码
```

这个方案最清楚，也最不容易误操作。

---

### 方案二：可以用，共用一个存储桶，但使用不同同步通道

如果为了省事，张三和李四共用一个 bucket，也可以这样：

张三：

```text
服务地址：相同
存储桶名称：company-obsidian-sync
访问密钥 ID：可以相同
访问密钥密码：可以相同
同步通道前缀：zhangsan
仓库 ID：zhangsan-vault
同步密码：张三自己的同步密码
```

李四：

```text
服务地址：相同
存储桶名称：company-obsidian-sync
访问密钥 ID：可以相同
访问密钥密码：可以相同
同步通道前缀：lisi
仓库 ID：lisi-vault
同步密码：李四自己的同步密码
```

这样远端数据会放在不同路径下面，不会被当成同一个仓库。

---

## 五、同一个人两台电脑怎么配置

同一个人的两台电脑，应该保持下面这些完全一致：

```text
服务地址
存储桶名称
同步通道前缀
仓库 ID
同步密码
```

例如张三的第一台电脑和第二台电脑：

```text
同步通道前缀：zhangsan
仓库 ID：zhangsan-vault
同步密码：张三自己的同步密码
```

这三项一样，张三的两台电脑才会同步同一份数据。

---

## 六、不同人共用访问密钥有什么风险

技术上，多个人可以共用同一个：

```text
服务地址
访问密钥 ID
访问密钥密码
存储桶名称
```

但从安全角度，不推荐长期这样做。

原因是：

```text
共用同一个访问密钥，代表大家拥有同一套对象存储权限。
```

即使同步密码不同，别人看不懂你的笔记内容，也可能出现这些问题：

```text
误删远端文件
覆盖远端文件
把同步通道填错后写到别人的位置
密钥泄露后影响所有人
```

所以更安全的做法是：

```text
不同用户使用不同访问密钥。
不同用户使用不同 bucket，或者至少使用不同同步通道前缀和仓库 ID。
```

---

## 七、会不会四台电脑串到一起

假设有四台电脑：

```text
张三电脑 A
张三电脑 B
李四电脑 A
李四电脑 B
```

不会串到一起的配置：

```text
张三电脑 A、B 使用同一个张三仓库 ID / 同步通道 / 同步密码。
李四电脑 A、B 使用同一个李四仓库 ID / 同步通道 / 同步密码。
张三和李四的仓库 ID / 同步通道不同。
```

可能串到一起的配置：

```text
张三和李四使用了完全相同的服务地址、存储桶、同步通道前缀、仓库 ID。
```

这种情况下，插件会认为他们在使用同一个远端仓库。

如果同步密码也相同：

```text
他们会看到同一份数据。
```

如果同步密码不同：

```text
通常会解密失败，或者出现无法正常读取的问题。
```

所以不要依赖“同步密码不同”来做主要隔离，正确做法是从仓库 ID / 同步通道上隔离。

---

## 八、最简单记忆规则

同一个人两台电脑：

```text
仓库 ID / 同步通道一样。
同步密码一样。
```

不同人之间：

```text
仓库 ID / 同步通道不一样。
同步密码不一样。
最好访问密钥也不一样。
```

一句话总结：

```text
服务地址和访问密钥可以相同，但真正隔离数据靠仓库 ID / 同步通道，保护内容靠同步密码。
```
