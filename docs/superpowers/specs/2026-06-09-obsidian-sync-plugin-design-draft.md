# Obsidian 跨设备同步插件设计草案 v0.1

> 状态：草案。底层架构和同步流程已确认；界面、设置与测试验收仍待调整和批准。

## 1. 产品目标

构建一个自用优先的 Obsidian 社区插件，在不同电脑以及电脑与手机之间同步同一仓库中的笔记和附件。

MVP 不包含商业账号、订阅、多租户和托管服务。远端采用 S3 兼容对象存储，默认同步 Markdown、图片、PDF 等用户内容，并排除 `.obsidian/`、缓存、隐藏文件和临时文件。

## 2. 核心原则

- 任何失败都不得静默丢失用户内容。
- 桌面端与移动端使用同一套 TypeScript 插件代码。
- 支持离线编辑，设备重新联网后最终收敛。
- 路径、文件内容和敏感元数据上传前均进行端到端加密。
- 同步协议不依赖中心服务器和全局写锁。
- 误删和旧内容默认保留 30 天。

## 3. 远端架构

远端存储以下四类加密对象：

1. 仓库元数据：仓库 ID、协议版本、加密参数和保留策略。
2. 设备注册信息：设备 ID、显示名称和设备日志位置。
3. 设备事件日志：每台设备只追加自己的日志分片。
4. 不可变内容对象：按密文内容标识保存文件版本。

每个本地创建、修改、移动或删除操作都会形成一个事件。事件包含设备 ID、逻辑时钟、内容哈希、父版本 ID 和操作所需的加密元数据。其他设备仅拉取尚未消费的日志分片，避免多个设备争抢同一个全局清单。

同步密码通过密钥派生函数生成仓库密钥。同步密码和对象存储凭据只保存在设备本地；远端无法解密文件名、内容和敏感事件字段，但仍可能观察对象数量、密文大小和访问时间。

## 4. 同步流程

首次设备创建远端仓库并生成仓库 ID、设备 ID 和加密参数。后续设备使用同一 S3 配置、仓库 ID 和同步密码加入，并设置独立设备名。

插件在本地维护：

- 路径与内容哈希索引；
- 文件当前版本及父版本关系；
- 各设备日志读取游标；
- 待上传事件和内容队列；
- 最近一次完整同步状态。

一次同步按以下顺序执行：

1. 扫描并收集本地变更。
2. 上传远端尚不存在的加密内容对象。
3. 追加本设备事件日志。
4. 拉取其他设备的新日志分片。
5. 计算所有已知事件对应的统一仓库状态。
6. 下载、解密并校验所需内容。
7. 通过临时文件和原子替换应用到本地仓库。
8. 持久化日志游标和同步结果。

上传成功前不清空待处理队列。远端内容只有在完整下载、认证解密和哈希校验成功后才替换本地文件。断网、应用挂起或部分请求失败后，下次同步从已保存进度继续；一次列表请求未看到对象不能被解释为删除。

默认在仓库打开时同步，本地变更经过短暂防抖后同步，应用活跃时定时拉取，并始终提供手动同步入口。移动端不承诺应用被系统挂起后的后台实时同步。

## 5. 冲突与删除

事件通过父版本关系识别因果更新和并发更新。

- 两台设备并发修改同一路径时，使用确定性排序选择原路径版本。
- 另一版本保存为带设备名和短版本号的冲突副本。
- 二进制附件使用同样的冲突保留规则。
- 删除与并发修改相遇时，修改优先保留，避免删除吞掉新内容。
- 重命名使用显式移动事件传播，而不是简单推断为删除加创建。
- 重复消费同一事件必须幂等，不能生成重复冲突副本。

逻辑删除立即同步，但删除墓碑和旧密文内容默认保留 30 天。活跃设备可以执行保守清理；无法确认所有已知设备均已越过安全游标时，不回收相关对象。

## 6. 故障处理

以下错误必须暂停受影响的远端变更，并显示可操作信息：

- 同步密码错误或密钥不匹配；
- 密文损坏、认证失败或内容哈希不一致；
- S3 凭据、权限、网络或配额错误；
- 不支持的远端协议版本；
- 本地磁盘空间不足或文件写入失败。

错误不能被静默跳过。重试必须保持幂等，且不能把不完整下载写入正式文件。
