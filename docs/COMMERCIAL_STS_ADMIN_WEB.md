# Commercial STS 客户授权管理页面

## 目标

商业化后的日常客户授权不再依赖终端命令。管理员只需登录网页，即可创建客户、签发和管理授权令牌。

管理员入口：

```text
https://sync.e2note.com/admin
```

管理员页面默认关闭；服务器完成一次性安全配置并部署新版本后才会开放。

## 客户与令牌规则

- 一个客户账号对应一个当前有效授权令牌。
- 同一客户的多台 Obsidian 设备共用该授权令牌。
- 每台设备仍使用同一个由客户自行设置的同步密码；同步密码不会提交到授权服务器。
- 令牌首次签发或重新签发时只显示一次，服务器只持久化令牌哈希。
- 重新签发会立即吊销该客户此前的有效令牌。
- 令牌丢失时不能找回原文，只能重新签发。
- 客户停用后，其令牌即使尚未到期也不能换取临时同步凭证。

## 页面操作

### 新建客户并签发

填写：

- 客户编号：例如 `customer_001`，建议使用订单号或内部客户编号，不要填写身份证号、手机号等敏感信息；
- 设备上限：个人客户通常填写 `2` 或 `3`；
- 有效天数：试用可填 `7` 或 `30`，正式订阅可填 `365`。

点击“创建并签发”后，页面只显示一次原始令牌。点击“复制令牌”，通过私密渠道交付客户；关闭或刷新页面后无法再次查看。

### 重新签发

客户令牌丢失、误发或疑似泄露时点击“重新签发”。页面会先要求确认，然后签发新令牌并立即使旧令牌失效。

### 续期

点击“续期”，按照页面当前的有效天数更新该客户的当前令牌。续期不会改变令牌原文，客户设备无需重新填写。

### 吊销

点击“吊销”会立即停止当前令牌。客户设备之后无法继续获取新的临时 OSS 凭证，除非重新签发。

### 停用与恢复

“停用”用于暂停整个客户账号；“恢复”重新允许账号使用尚有效的令牌。停用不会显示、复制或删除任何令牌原文。

## 安全边界

- 管理员页面只允许 HTTPS。
- 页面使用独立管理员密码、短时 HttpOnly 安全会话、SameSite 严格 Cookie 和 CSRF 校验。
- 登录失败有频率限制。
- 管理员密码至少 16 个字符，不能与同步密码、云账号密码或 AccessKey 复用。
- 管理员密码、客户令牌、AccessKey、Secret、SecurityToken、同步密码、设备 ID 和哈希盐都不得写入 Git、文档、截图或聊天。
- 页面客户列表仅显示业务状态、设备数量、令牌数量和到期时间。

## 一次性部署配置

服务器部署人员在受限的服务器配置中设置：

```dotenv
ADMIN_ENABLED=false
ADMIN_PASSWORD=
ADMIN_SESSION_TTL_MINUTES=480
```

示例中的 `ADMIN_PASSWORD` 必须保持为空，直到管理员本人通过一次性本地安全输入页面安装独立强密码。密码安装完成后才能启用管理员页面并重建后端服务；Codex 不读取、不输出、不复制该密码。

## 已修复的持久化问题

持久化存储现在会在读取和写入前重新加载最新磁盘状态。即使运营 CLI 或管理员页面新增客户和令牌，正在运行的授权服务也能立即看到新数据，不会再由旧内存状态覆盖新签发记录。

## 当前交付边界

本地代码、测试和构建完成不等于生产页面已经开放。生产启用仍需：

1. 管理员本人设置一次管理员强密码；
2. 部署新后端并保持管理员页面默认关闭直至密码就绪；
3. 验证未登录访问、错误密码、正确登录、创建测试客户、一次性签发、续期、吊销和重新签发；
4. 删除测试令牌及临时交付文件；
5. 运行 `/healthz`、`/readyz`、真实 STS 和 OSS 五项验收。
