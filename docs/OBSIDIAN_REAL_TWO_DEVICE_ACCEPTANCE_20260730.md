# 商业 STS：真实 Obsidian 双端安装与验收

## 1. 验收目标

在两台真实设备的 Obsidian 中安装同一个 `0.1.1` 发布包，使用商业 STS 模式连接同一远端仓库，完成：

- 第一台到第二台同步。
- 第二台到第一台同步。
- 修改与删除传播。
- Obsidian 重启后的再次连接和同步。

只有这些真实操作完成后，阶段 D 才能标记为通过。

## 2. 发布包

```text
release/obsidian-sync-plugin-0.1.1-commercial-sts-20260730-094309.zip
```

SHA-256：

```text
1C7FBC17D3AFC2C6C898DB95EFA4EE9792A8201DE587AEFA6568DD1DA2BD575B
```

包内只能有：

```text
main.js
manifest.json
styles.css
OBSIDIAN_SYNC_PLUGIN_USER_MANUAL.md
```

## 3. 安全规则

- 两台设备先分别备份本地笔记库。
- 推荐先用两个专用测试库验收，避免第一次操作影响正式笔记。
- 不要复制、发送或覆盖 `data.json`。
- 不要在聊天、截图、录屏或验收记录中展示授权令牌、同步密码、设备 ID 或任何临时凭证。
- 两台设备填写同一个有效授权令牌和完全相同的同步密码，但各自保留插件自动生成的独立设备身份。
- 不要手动修改仓库 ID，不要点击“重新创建仓库”。

## 4. 每台设备安装发布包

以下步骤在两台设备上各执行一次。

1. 退出 Obsidian。
2. 在该设备的笔记库中创建目录：

```text
<笔记库>\.obsidian\plugins\obsidian-sync-plugin\
```

3. 把发布 zip 中的四个文件直接解压到这个目录。
4. 最终至少确认：

```text
<笔记库>\.obsidian\plugins\obsidian-sync-plugin\main.js
<笔记库>\.obsidian\plugins\obsidian-sync-plugin\manifest.json
<笔记库>\.obsidian\plugins\obsidian-sync-plugin\styles.css
```

5. 如果该目录已有旧版本，先备份目录，只覆盖发布包中的运行文件；不要删除或覆盖已有的 `data.json`。
6. 打开 Obsidian，进入：

```text
设置 -> 第三方插件 -> E2EE Sync -> 启用
```

7. 在插件列表确认版本为 `0.1.1`。

## 5. 第一台设备配置与首次上传

1. 打开：

```text
设置 -> E2EE Sync
```

2. “使用模式”选择：

```text
商业模式：授权服务
```

3. 授权服务地址填写：

```text
https://sync.e2note.com
```

4. 在 Obsidian 内输入有效授权令牌；不要把令牌发到聊天中。
5. 设置一个强同步密码，并保存在密码管理器中。
6. 依次点击：

```text
检查配置
测试连接
```

7. 两项通过后，在测试库创建：

```text
_commercial-sts-acceptance/A-to-B.md
```

8. 文件中只写非敏感验收文字，例如当前时间和 `A_TO_B_PASS_MARKER`。
9. 点击“同步”，等待成功提示。
10. 点击“复制第二台配置”。

复制内容会包含同一远端仓库所需的非秘密身份信息，但不会包含授权令牌、同步密码或设备 ID。

## 6. 第二台设备加入同一仓库

1. 在第二台安装并启用同一个发布包。
2. 打开：

```text
设置 -> E2EE Sync
```

3. 点击“粘贴配置”。
4. 确认模式为“商业模式：授权服务”，授权服务地址为 `https://sync.e2note.com`。
5. 在第二台 Obsidian 内重新输入同一个有效授权令牌。
6. 输入与第一台完全相同的同步密码。
7. 依次点击：

```text
检查配置
测试连接
同步
```

8. 确认第二台出现 `A-to-B.md`，内容与第一台一致。

如果两台设备之间没有共享剪贴板，可以临时通过可信通道传递“复制第二台配置”生成的文本；粘贴成功后删除临时副本，不要把它放进同步库或 Git。

## 7. 双向与删除验收

### 第二台到第一台

1. 第二台在 `A-to-B.md` 末尾追加 `B_TO_A_PASS_MARKER`。
2. 第二台新建：

```text
_commercial-sts-acceptance/B-to-A.md
```

3. 第二台点击“同步”。
4. 第一台点击“同步”。
5. 第一台确认追加内容和 `B-to-A.md` 均正确出现。

### 删除传播

1. 第一台新建：

```text
_commercial-sts-acceptance/delete-me.md
```

2. 第一台同步，第二台同步并确认文件出现。
3. 第二台删除 `delete-me.md` 并同步。
4. 第一台再次同步，确认该文件被删除。

### 重启复验

1. 完全退出两台 Obsidian。
2. 重新打开两台 Obsidian。
3. 两台分别再次点击“测试连接”和“同步”。
4. 确认没有授权、解密、仓库不一致或设备超限错误。

- [ ] 删除操作可正确传播。
- [ ] 重启 Obsidian 后再次连接和同步成功。
- [ ] 未复制 `data.json`，未手动修改仓库 ID，未共享设备 ID。
- [ ] 截图和日志中没有授权令牌、同步密码或临时凭证。

## 9. 失败时记录

只记录以下脱敏信息：

```text
设备：第一台 / 第二台
阶段：安装 / 检查配置 / 测试连接 / 上传 / 下载 / 删除 / 重启
用户界面错误类别
HTTP 状态（如果界面显示）
是否可稳定复现
```

不要记录或发送设置字段的真实内容。
